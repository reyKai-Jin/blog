JavaScript 是单线程的，但定时器、网络回调、Promise 回调却能「同时」推进。理解事件循环，才能预测代码真实的执行顺序。

## 核心组成

- **调用栈**：同步代码执行的地方
- **宏任务队列**：`setTimeout`、`setInterval`、I/O、UI 事件
- **微任务队列**：Promise 回调、`queueMicrotask`、`MutationObserver`
- **渲染帧**：每帧一次，浏览器决定何时绘制

执行顺序：

1. 执行一个宏任务（整段同步代码也算一个）
2. 清空所有微任务（包括微任务里新产生的微任务）
3. 必要时渲染
4. 取下一个宏任务，重复

关键点：**每执行完一个宏任务，都会把微任务队列清空**，然后才轮到下一个宏任务。

## 经典题目

```js
console.log("1");

setTimeout(() => console.log("2"), 0);

Promise.resolve().then(() => console.log("3"));

console.log("4");
```

输出：

```text
1
4
3
2
```

原因：`1`、`4` 是同步代码先执行；Promise 回调进入微任务队列，当前宏任务结束后立即清空；`setTimeout` 属于下一个宏任务。

## await 的顺序

```js
async function foo() {
  console.log("a");
  await null;
  console.log("b");
}

console.log("start");
foo();
console.log("end");
```

输出：

```text
start
a
end
b
```

`await` 之前的代码同步执行，`await` 之后的代码相当于放进微任务。

```js
async function bar() {
  console.log("x");
  await Promise.resolve();
  console.log("y");
}

bar();
Promise.resolve().then(() => console.log("z"));
```

输出 `x y z`：`bar` 里 `await` 的后续先入队，`z` 的回调后入队。

## 微任务会「插队」

```js
setTimeout(() => console.log("timeout"), 0);

Promise.resolve().then(() => {
  console.log("promise 1");
  Promise.resolve().then(() => console.log("promise 2"));
});

console.log("sync");
```

输出：

```text
sync
promise 1
promise 2
timeout
```

微任务里产生的微任务会在当前清空阶段继续执行，不会等到下一个宏任务。

## 微任务与渲染

渲染发生在微任务清空之后。也就是说，在微任务里连续修改 DOM，浏览器只会绘制一次：

```js
element.style.width = "100px";
Promise.resolve().then(() => {
  element.style.width = "200px";
});
// 用户只会看到 200px
```

如果在 `setTimeout` 里修改，则会先绘制一次再绘制第二次，可能看到闪烁。

`requestAnimationFrame` 回调在渲染前执行，适合做动画：

```js
function loop() {
  update();
  requestAnimationFrame(loop);
}
```

## 定时器不精确

```js
const start = performance.now();

setTimeout(() => {
  console.log(performance.now() - start); // 通常大于 100
}, 100);
```

`setTimeout(fn, 0)` 也不是立即执行，浏览器对嵌套定时器有最小延迟（约 4ms），而且必须等当前任务和微任务全部结束。

长时间运行的同步代码会阻塞定时器和渲染：

```js
// 阻塞主线程 2 秒，页面卡死
const end = Date.now() + 2000;
while (Date.now() < end) {}
```

需要处理大量数据时，用 Web Worker 或分片执行。

## Node.js 的差异

Node 的事件循环分为多个阶段：`timers`、`pending callbacks`、`poll`、`check`、`close callbacks`，每个阶段之间清空微任务。

常见差异：

```js
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));
```

在主模块中，两者的顺序不确定；在 I/O 回调里，`setImmediate` 通常先于 `setTimeout`。

Node 中 `process.nextTick` 的优先级高于 Promise 微任务。

## 实际应用

- 把大任务拆成多个微任务或宏任务，避免阻塞渲染
- 需要等 DOM 更新后再测量尺寸：`await nextTick()`（Vue）或 `queueMicrotask`
- 动画用 `requestAnimationFrame`，不要用 `setTimeout`
- 节流、防抖本质上是在控制任务进入队列的频率
- 排查「为什么日志顺序不对」时，先区分同步、微任务、宏任务

## 小结

- 一轮循环：一个宏任务 → 清空微任务 → 渲染 → 下一个宏任务
- Promise 回调和 `await` 后续都是微任务
- 微任务可以「插队」，宏任务只能排队
- 同步代码会阻塞一切，长任务要拆分或移到 Worker
