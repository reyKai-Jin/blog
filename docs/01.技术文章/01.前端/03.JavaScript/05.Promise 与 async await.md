异步代码从回调地狱走到 `async/await`，可读性好了很多，但错误处理和并发控制仍然是高频出错点。

## Promise 基础

```js
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve("成功");
  }, 1000);
});

promise.then(
  value => console.log(value),
  error => console.error(error)
);
```

三种状态：

- `pending`：进行中
- `fulfilled`：已成功
- `rejected`：已失败

状态一旦改变就不可逆，`resolve` 和 `reject` 只有第一次生效。

## then 的返回值

`then` 总是返回一个新的 Promise，这是链式调用的基础：

```js
fetch("/api/user")
  .then(res => res.json())
  .then(user => fetch(`/api/orders?userId=${user.id}`))
  .then(res => res.json())
  .then(orders => console.log(orders))
  .catch(error => console.error("任意一步失败", error));
```

返回值规则：

- 返回普通值：下一个 `then` 收到这个值
- 返回 Promise：等待它完成
- 抛出异常：进入最近的 `catch`

```js
Promise.resolve(1)
  .then(value => {
    return value + 1;
  })
  .then(value => {
    console.log(value); // 2
  });
```

## 错误处理

```js
fetch("/api/data")
  .then(res => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  })
  .catch(error => {
    console.error("请求失败", error);
  })
  .finally(() => {
    console.log("无论成功失败都会执行");
  });
```

注意：`fetch` 只在网络错误时 reject，HTTP 404/500 仍然是 resolved，需要手动判断 `res.ok`。

`catch` 之后可以继续链式调用：

```js
fetch("/api/data")
  .catch(() => ({ fallback: true }))
  .then(data => {
    console.log("始终能拿到数据", data);
  });
```

## 组合方法

```js
const p1 = Promise.resolve(1);
const p2 = Promise.resolve(2);

Promise.all([p1, p2]).then(values => console.log(values)); // [1, 2]
```

| 方法                 | 行为                                 |
| -------------------- | ------------------------------------ |
| `Promise.all`        | 全部成功才成功，任意一个失败立即失败 |
| `Promise.allSettled` | 等待全部结束，返回每个结果的状态     |
| `Promise.race`       | 第一个结束的（成功或失败）决定结果   |
| `Promise.any`        | 第一个成功的决定结果，全部失败才失败 |

```js
const results = await Promise.allSettled([p1, p2]);

results.forEach(result => {
  if (result.status === "fulfilled") {
    console.log(result.value);
  } else {
    console.error(result.reason);
  }
});
```

## async/await

`async` 函数总是返回 Promise，`await` 等待 Promise 完成：

```js
async function loadUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}

async function main() {
  try {
    const user = await loadUser(1);
    console.log(user);
  } catch (error) {
    console.error(error);
  }
}
```

`await` 只是 `then` 的语法糖，不会阻塞主线程。

## 串行与并发

串行：一个接一个，总耗时是总和。

```js
const user = await getUser();
const orders = await getOrders(user.id);
const stats = await getStats(user.id);
```

并发：互不依赖的请求同时发出。

```js
const [user, orders, stats] = await Promise.all([getUser(), getOrders(), getStats()]);
```

错误处理也不同：

- `Promise.all` 任意一个失败就整体失败
- 想让每个请求独立成败，用 `Promise.allSettled`
- 给每个 Promise 单独加 `catch`，可以保留部分结果

## 常见坑

### 在 forEach 里用 async

```js
// 不会等待，main 会在请求完成前结束
items.forEach(async item => {
  await save(item);
});

// 正确：用 for...of 串行
for (const item of items) {
  await save(item);
}

// 或者并发
await Promise.all(items.map(item => save(item)));
```

### 忘写 await

```js
async function update() {
  save(data); // 错误没被捕获
  return "done";
}
```

未处理的 rejected Promise 会触发 `unhandledrejection`，在浏览器里表现为控制台报错。

### 在循环里重复 await 同一个 Promise

```js
const result = getUser();
await result;
await result; // 不会重新请求，只是重复等待同一个 Promise
```

### 构造函数里不能直接 await

```js
class Store {
  constructor() {
    // 不允许
    // this.data = await load();
  }

  static async create() {
    const store = new Store();
    store.data = await load();
    return store;
  }
}
```

用静态异步工厂方法替代。

## 超时控制

```js
function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) => {
    setTimeout(() => reject(new Error("请求超时")), ms);
  });

  return Promise.race([promise, timeout]);
}

const data = await withTimeout(fetch("/api/slow"), 5000);
```

现代浏览器也可以用 `AbortController` 取消请求。

## 小结

- `then` 返回新 Promise，链式调用靠返回值传递
- `fetch` 的 HTTP 错误不会自动 reject，要检查 `res.ok`
- 并发用 `Promise.all` / `allSettled`，不要写成串行
- `for...of` + `await` 串行，`map` + `Promise.all` 并发
- 异步构造函数用静态工厂方法
