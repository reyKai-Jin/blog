JavaScript 没有传统意义上的类，`class` 只是原型继承的语法糖。理解原型链，才能解释属性查找、`instanceof` 和继承行为。

## 三个关键概念

```js
function Person(name) {
  this.name = name;
}

Person.prototype.say = function () {
  console.log(this.name);
};

const p = new Person("金凯");
```

- `Person.prototype`：构造函数的**原型对象**，供实例共享方法
- `p.__proto__`：实例的原型引用，等于 `Person.prototype`
- `p.constructor`：指向 `Person`

```js
p.__proto__ === Person.prototype; // true
p.constructor === Person; // true
Person.prototype.constructor === Person; // true
```

`__proto__` 是历史遗留的访问器，标准写法是：

```js
Object.getPrototypeOf(p) === Person.prototype; // true
```

## new 做了什么

```js
function myNew(Ctor, ...args) {
  // 1. 创建以 Ctor.prototype 为原型的新对象
  const obj = Object.create(Ctor.prototype);

  // 2. 执行构造函数，this 指向新对象
  const result = Ctor.apply(obj, args);

  // 3. 构造函数返回对象则用它，否则返回新对象
  return result !== null && typeof result === "object" ? result : obj;
}
```

## 原型链查找

访问属性时，先查对象自身，没有就沿 `__proto__` 往上找，直到 `null`：

```js
p.name; // 自身属性
p.say; // 从 Person.prototype 找到
p.toString; // Object.prototype 上的方法
```

原型链终点：

```js
Person.prototype.__proto__ === Object.prototype; // true
Object.prototype.__proto__ === null; // true
```

### instanceof

```js
p instanceof Person; // true
p instanceof Object; // true
```

`instanceof` 检查构造函数的 `prototype` 是否出现在对象的原型链上。

## 常见写法对比

```js
// 每个实例一份方法，浪费内存
function A() {
  this.say = () => console.log("a");
}

// 方法放原型，实例共享
function B() {}
B.prototype.say = function () {
  console.log("b");
};

// 更直接
const proto = { say: () => console.log("c") };
const c = Object.create(proto);
```

`Object.create(proto)` 创建的对象直接以 `proto` 为原型，没有构造函数调用。

## class 语法

```js
class Person {
  constructor(name) {
    this.name = name;
  }

  say() {
    console.log(this.name);
  }

  static create(name) {
    return new Person(name);
  }

  get label() {
    return `Person: ${this.name}`;
  }

  set label(value) {
    this.name = value;
  }
}

const p = new Person("金凯");
p.say();
Person.create("Jin Kai");
```

`class` 与构造函数的关键差异：

- `class` 声明不会提升（存在 TDZ）
- 类内部默认是严格模式
- 类的方法不可枚举
- 必须用 `new` 调用，直接调用会报错

## 继承

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    console.log(`${this.name} 发出声音`);
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name); // 必须先调用 super
    this.breed = breed;
  }

  speak() {
    super.speak();
    console.log("汪汪");
  }
}

const dog = new Dog("旺财", "柴犬");
dog.speak();
```

- 子类构造函数里必须先 `super()` 才能使用 `this`
- `super.method()` 调用父类方法
- `extends` 同时继承静态方法

### 内置类型继承

```js
class MyArray extends Array {
  first() {
    return this[0];
  }
}

const arr = new MyArray(1, 2, 3);
arr.first(); // 1
arr instanceof MyArray; // true
```

数组、错误、Map 等内置类型可以用 `extends` 正常继承。

## 私有字段

```js
class Counter {
  #count = 0; // 私有字段

  increment() {
    this.#count += 1;
    return this.#count;
  }
}

const counter = new Counter();
counter.increment();
counter.#count; // SyntaxError
```

以 `#` 开头的字段只能在类内部访问，是真正的私有，不是约定。

## 静态成员

```js
class Config {
  static defaultTheme = "dark";

  static load() {
    return this.defaultTheme;
  }
}

Config.defaultTheme; // "dark"
Config.load(); // "dark"
```

静态成员挂在类本身，不属于实例。

## 实践建议

- 需要共享的方法放原型或 class 方法，不要每个实例创建一份
- 优先用 `class` 表达有状态的实体
- 用组合和纯函数替代多层继承
- 私有字段用 `#`，不要再用 `_name` 的约定
- 不要随意修改内置对象的原型

## 小结

- `prototype` 是构造函数上的对象，`__proto__` 是实例指向原型的引用
- 属性查找沿原型链进行，直到 `null`
- `class` 是原型继承的语法糖，行为更严格
- `extends` + `super` 完成继承，私有字段用 `#`
