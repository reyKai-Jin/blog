`var` 和 `let` 的差异不只是「能不能重复声明」。作用域、提升、暂时性死区、全局对象绑定，每一条都能让代码行为完全不同。

<!-- more -->

## 三种声明

```js
var a = 1;
let b = 2;
const c = 3;
```

|               | `var`                      | `let`          | `const`        |
| ------------- | -------------------------- | -------------- | -------------- |
| 作用域        | 函数作用域                 | 块级作用域     | 块级作用域     |
| 重复声明      | 允许                       | 报错           | 报错           |
| 变量提升      | 提升并初始化为 `undefined` | 提升但不初始化 | 提升但不初始化 |
| 暂时性死区    | 没有                       | 有             | 有             |
| 挂到 `window` | 是（全局时）               | 否             | 否             |
| 重新赋值      | 可以                       | 可以           | 不可以         |

## 函数作用域与块级作用域

```js
function demo() {
  if (true) {
    var x = 1;
    let y = 2;
  }

  console.log(x); // 1
  console.log(y); // ReferenceError: y is not defined
}
```

`var` 只认函数边界，`if`、`for`、`try` 的 `{}` 都不算；`let` / `const` 认所有块。

```js
for (var i = 0; i < 3; i++) {}
console.log(i); // 3，泄漏到外层

for (let j = 0; j < 3; j++) {}
console.log(j); // ReferenceError
```

## 变量提升

`var` 的声明会被提升到函数顶部，赋值留在原处：

```js
console.log(a); // undefined，而不是报错
var a = 1;
```

等价于：

```js
var a;
console.log(a);
a = 1;
```

函数声明也会提升，并且可以完整调用：

```js
sayHi(); // 正常执行

function sayHi() {
  console.log("hi");
}
```

但函数表达式不会：

```js
sayHi(); // TypeError: sayHi is not a function

var sayHi = function () {
  console.log("hi");
};
```

## 暂时性死区（TDZ）

`let` / `const` 声明的变量在进入作用域时就已经存在，但在声明语句执行前不能被访问：

```js
{
  console.log(value); // ReferenceError: Cannot access 'value' before initialization
  let value = 1;
}
```

这段代码不会输出 `undefined`，而是直接抛错。TDZ 的范围是从进入块开始，到声明语句执行结束。

```js
let name = "金凯";

{
  console.log(name); // ReferenceError
  let name = "其他";
}
```

内层的 `let name` 让整个块进入 TDZ，外层的同名变量被遮蔽。

## const 不等于不可变

`const` 锁定的是绑定，不是值：

```js
const user = { name: "金凯" };
user.name = "Jin Kai"; // 允许
user = {}; // TypeError: Assignment to constant variable
```

要真正冻结对象：

```js
const config = Object.freeze({ theme: "dark" });
config.theme = "light"; // 静默失败（非严格模式）或抛错（严格模式）
```

但 `Object.freeze` 是浅冻结，嵌套对象仍然可变，需要递归处理。

## 全局变量

```js
var globalVar = 1;
let globalLet = 2;

console.log(window.globalVar); // 1
console.log(window.globalLet); // undefined
```

浏览器里 `var` 在全局作用域会挂到 `window`，`let` / `const` 不会。这也是为什么用 `let` 声明全局变量不会污染 `window`。

未声明的赋值会隐式创建全局变量：

```js
function leak() {
  accidental = 1; // 严格模式下报错
}
```

这就是应该开启 `"use strict"`（或使用模块）的原因之一。

## 实践建议

- 默认用 `const`，需要重新赋值时再用 `let`
- 不要用 `var`，除非在维护老代码
- 变量声明尽量靠近使用位置，缩小作用域
- 块级作用域内不要重复声明同名变量
- 模块天然是严格模式，不需要手动写 `"use strict"`

## 小结

- `var` 函数作用域 + 提升为 `undefined`，`let` / `const` 块级作用域 + TDZ
- 函数声明会提升，函数表达式不会
- `const` 只保证绑定不变，对象内容仍可修改
- 理解 TDZ 能解释大部分「变量未初始化」的诡异报错
