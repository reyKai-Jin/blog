「把数据放到浏览器里」有不止一种做法。选错了存储，轻则性能变差，重则用户数据说没就没。这篇对比 localStorage、sessionStorage 和 IndexedDB。

<!-- more -->

## 三种存储速览

|            | localStorage       | sessionStorage | IndexedDB          |
| ---------- | ------------------ | -------------- | ------------------ |
| 容量       | 约 5MB             | 约 5MB         | 通常几百 MB 起     |
| 生命周期   | 永久，除非手动清除 | 当前标签页会话 | 永久，除非手动清除 |
| 读写方式   | 同步               | 同步           | 异步               |
| 数据类型   | 字符串             | 字符串         | 结构化数据、二进制 |
| API 复杂度 | 极低               | 极低           | 较高               |
| 主线程阻塞 | 会                 | 会             | 不会               |

## localStorage

```js
// 写入
localStorage.setItem("theme", "dark");
localStorage.setItem("user", JSON.stringify({ name: "金凯", id: 1 }));

// 读取
const theme = localStorage.getItem("theme"); // "dark" 或 null
const user = JSON.parse(localStorage.getItem("user") || "null");

// 删除
localStorage.removeItem("theme");
localStorage.clear(); // 清空当前域名下所有数据
```

注意事项：

- 只能存字符串，对象要先 `JSON.stringify`
- 同步 API，**大数据量会阻塞主线程**
- 无痕模式下部分浏览器会抛异常，读写要包 `try / catch`
- 同一域名共享，多个标签页可以互相覆盖

```js
function safeGet(key) {
  try {
    return localStorage.getItem(key);
  } catch {
    return null;
  }
}
```

## 跨标签页同步

`storage` 事件可以在其他标签页修改数据时收到通知：

```js
window.addEventListener("storage", event => {
  if (event.key === "theme") {
    applyTheme(event.newValue);
  }
});
```

注意：触发事件的标签页本身**收不到**通知，只有其他同源窗口会收到。

## sessionStorage

API 和 localStorage 完全一样，区别只在生命周期：

- 只在当前标签页有效
- 关闭标签页即清除
- 新开一个标签页不会共享（通过 `window.open` 打开的初始会复制一份，之后独立）

适合存表单草稿、一次性流程状态、页面内的临时标记。

## IndexedDB

需要存大量数据、文件、离线缓存时用 IndexedDB。它基于事务，API 是异步的。

### 打开数据库

```js
const request = indexedDB.open("my-site", 1);

request.onupgradeneeded = event => {
  const db = event.target.result;

  // 创建对象仓库（类似表），并指定主键
  if (!db.objectStoreNames.contains("articles")) {
    const store = db.createObjectStore("articles", { keyPath: "id" });
    store.createIndex("byDate", "date");
  }
};

request.onsuccess = event => {
  const db = event.target.result;
  // 使用 db
};

request.onerror = event => {
  console.error("打开数据库失败", event.target.error);
};
```

### 增删改查

```js
function addArticle(db, article) {
  const tx = db.transaction("articles", "readwrite");
  const store = tx.objectStore("articles");

  store.put(article); // put 存在则覆盖，add 存在则报错

  tx.oncomplete = () => console.log("写入完成");
  tx.onerror = () => console.error("写入失败", tx.error);
}

function getArticle(db, id) {
  return new Promise((resolve, reject) => {
    const tx = db.transaction("articles", "readonly");
    const request = tx.objectStore("articles").get(id);

    request.onsuccess = () => resolve(request.result);
    request.onerror = () => reject(request.error);
  });
}
```

查询全部：

```js
const tx = db.transaction("articles", "readonly");
const request = tx.objectStore("articles").getAll();

request.onsuccess = () => {
  console.log(request.result); // 数组
};
```

### 索引与范围查询

```js
const index = tx.objectStore("articles").index("byDate");
const request = index.getAll(IDBKeyRange.lowerBound("2026-01-01"));

request.onsuccess = () => console.log(request.result);
```

### 版本升级

- 数据库结构变化时提升版本号
- `onupgradeneeded` 里创建 / 删除对象仓库和索引
- 不要在旧版本里删数据，先迁移再删

## 什么时候用哪个

- 主题、语言、登录标记等小配置：`localStorage`
- 当前标签页的临时状态：`sessionStorage`
- 离线文章、图片缓存、音频片段、大量列表：`IndexedDB`
- 需要和服务端同步、跨设备共享：不要存浏览器，存服务端

## 安全提醒

- 本地存储可以被同源脚本任意读取，**不要存密码、token 明文**
- XSS 一旦发生，localStorage 里的所有内容都会泄露
- 用户清除浏览器数据时内容会丢失，重要数据必须有服务端备份

## 小结

- 小字符串配置用 localStorage，会话状态用 sessionStorage
- 大量结构化数据用 IndexedDB，避免同步阻塞
- 读写都要考虑异常和用户清除数据的情况
- 敏感信息永远不要只存在浏览器
