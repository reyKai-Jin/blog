一个页面能不能维护，往往在写第一行 HTML 时就决定了。这篇从文档骨架开始，梳理 HTML5 的语义化标签和常见的结构错误。

## 文档骨架

一份最小的 HTML5 文档长这样：

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>页面标题</title>
    <meta name="description" content="一句话说明这个页面是做什么的" />
  </head>
  <body>
    <main>页面内容</main>
  </body>
</html>
```

几个容易忽略的点：

- `<!DOCTYPE html>` 必须写在第一行，否则浏览器会进入怪异模式（quirks mode）
- `lang` 影响屏幕阅读器的发音、翻译提示和断词规则，中文站写 `zh-CN`
- `viewport` 是移动端适配的前提，缺少它页面会按 980px 宽度缩放
- `charset` 尽量放在 `<head>` 最前面，避免解析到一半才发现编码

## 页面级语义标签

| 标签      | 作用                 | 使用要点                                        |
| --------- | -------------------- | ----------------------------------------------- |
| `header`  | 页头或区块头部       | 可以出现在 `body` 内，也可以出现在 `article` 内 |
| `nav`     | 导航链接集合         | 只用于主要导航，正文里的一串链接不算            |
| `main`    | 页面主体内容         | 每页只应有一个，且不能嵌套                      |
| `article` | 可独立分发的内容     | 博客文章、新闻、评论条目                        |
| `section` | 有主题的内容分组     | 通常需要一个标题                                |
| `aside`   | 与主内容弱相关的补充 | 侧边栏、广告、相关推荐                          |
| `footer`  | 页脚或区块底部       | 版权、联系方式、相关链接                        |

一个典型的文章页结构：

```html
<body>
  <header>
    <a href="/">站点名</a>
    <nav aria-label="主导航">
      <a href="/tech">技术文章</a>
      <a href="/about">关于</a>
    </nav>
  </header>

  <main>
    <article>
      <header>
        <h1>文章标题</h1>
        <p>
          <time datetime="2026-11-14">2026-11-14</time>
        </p>
      </header>

      <section aria-labelledby="section-1">
        <h2 id="section-1">小节标题</h2>
        <p>正文内容</p>
      </section>
    </article>

    <aside aria-label="相关文章">
      <h2>相关文章</h2>
      <ul>
        <li><a href="/tech/html5/forms-and-validation">表单增强</a></li>
      </ul>
    </aside>
  </main>

  <footer>
    <p>© 2026 金凯</p>
  </footer>
</body>
```

## 标题层级

标题层级表达的是文档大纲，不是字号：

- 一个页面通常只有一个 `h1`，与页面主题对应
- 不要为了「字小一点」跳级使用 `h3`，样式交给 CSS
- `article`、`section` 内部可以从 `h2` 重新开始

```html
<h1>HTML5 语义化</h1>
<h2>文档骨架</h2>
<h3>meta 标签</h3>
<h2>页面结构</h2>
```

## 语义化不等于全是 div

需要判断的是「这块内容是什么」，而不是「它长什么样」：

```html
<!-- 不推荐：看不出结构 -->
<div class="header">
  <div class="nav">...</div>
</div>
<div class="content">
  <div class="post">...</div>
</div>

<!-- 推荐：标签本身就说明了内容 -->
<header>
  <nav>...</nav>
</header>
<main>
  <article>...</article>
</main>
```

但也不要走极端：纯粹用于布局的容器仍然应该用 `div`，比如 Flex 布局的包装层。

## 可访问性要点

语义标签的另一个价值是服务屏幕阅读器，配合 ARIA 使用效果更好：

```html
<nav aria-label="主导航">...</nav>
<button aria-expanded="false" aria-controls="menu">菜单</button>
<img src="/cover.webp" alt="城市夜景短片的封面" />
```

- 装饰性图片写 `alt=""`，让屏幕阅读器跳过
- 图标按钮必须有可读文本，可以用 `aria-label` 或视觉隐藏文字
- 不要用 `div` 加 `onclick` 冒充按钮，键盘用户无法操作

## 小结

- 先写 `DOCTYPE`、`lang`、`viewport`，再写内容
- 用 `header` / `nav` / `main` / `article` / `section` / `footer` 表达结构
- 标题层级表达大纲，样式交给 CSS
- 语义化的最终目标是可读、可维护、可访问
