很多表单校验其实不需要写 JavaScript，浏览器已经提供了类型、约束和校验 API。这篇整理 HTML5 表单里真正高频的部分。

## 新的 input 类型

| 类型                      | 典型用途 | 原生行为                           |
| ------------------------- | -------- | ---------------------------------- |
| `email`                   | 邮箱     | 移动端弹出邮箱键盘，校验格式       |
| `url`                     | 网址     | 校验是否为合法 URL                 |
| `tel`                     | 电话     | 只负责弹数字键盘，不校验格式       |
| `number`                  | 数字     | 上下箭头，`min` / `max` / `step`   |
| `range`                   | 滑块     | 配合 `min` / `max` / `step`        |
| `date` / `month` / `week` | 日期     | 原生日期选择器                     |
| `time` / `datetime-local` | 时间     | 原生时间选择器                     |
| `color`                   | 颜色     | 原生取色器                         |
| `search`                  | 搜索框   | 支持一键清除                       |
| `file`                    | 文件     | 配合 `accept`、`multiple` 限制类型 |

```html
<form>
  <label>
    邮箱
    <input type="email" name="email" required autocomplete="email" />
  </label>

  <label>
    主页
    <input type="url" name="homepage" placeholder="https://" />
  </label>

  <label>
    年龄
    <input type="number" name="age" min="1" max="120" step="1" />
  </label>

  <label>
    出生日期
    <input type="date" name="birthday" />
  </label>

  <button type="submit">提交</button>
</form>
```

注意：`type="number"` 只适合真正参与计算的数字，像手机号、身份证号应该用 `tel` 或 `text` + `inputmode`，否则会丢前导零、允许科学计数法。

## 输入模式与自动填充

```html
<!-- 移动端键盘类型，不改变 input 的校验行为 -->
<input type="text" inputmode="numeric" pattern="[0-9]*" />

<!-- 自动填充提示，告诉浏览器这里该填什么 -->
<input name="password" type="password" autocomplete="current-password" />
<input name="new-password" type="password" autocomplete="new-password" />
```

常用 `autocomplete` 值：`name`、`email`、`tel`、`street-address`、`postal-code`、`one-time-code`。

## 约束校验属性

```html
<input
  type="text"
  name="username"
  required
  minlength="3"
  maxlength="16"
  pattern="[a-zA-Z0-9_]+"
  title="只能包含字母、数字和下划线"
/>
```

- `required`：必填
- `minlength` / `maxlength`：字符数限制
- `min` / `max` / `step`：数值或日期的范围
- `pattern`：正则表达式，注意是**整体匹配**，不需要写 `^` 和 `$`
- `title`：校验失败时的提示文案

`pattern` 在部分浏览器里不支持 `u` 标志和某些高级语法，复杂规则还是交给 JavaScript。

## Validity API

浏览器会把每个控件的校验状态挂在 `validity` 对象上：

```js
const input = document.querySelector('input[name="username"]');

input.addEventListener("input", () => {
  const { valid, valueMissing, patternMismatch } = input.validity;

  if (valid) {
    input.setCustomValidity("");
  } else if (valueMissing) {
    input.setCustomValidity("用户名不能为空");
  } else if (patternMismatch) {
    input.setCustomValidity("只能包含字母、数字和下划线");
  }
});
```

常用接口：

| 成员                                        | 说明                                |
| ------------------------------------------- | ----------------------------------- |
| `checkValidity()`                           | 返回是否通过，并触发 `invalid` 事件 |
| `reportValidity()`                          | 校验并显示原生提示                  |
| `setCustomValidity(msg)`                    | 设置自定义错误，传空字符串清除      |
| `validity.valueMissing`                     | 必填但为空                          |
| `validity.typeMismatch`                     | 类型不匹配（如 email）              |
| `validity.patternMismatch`                  | 正则不匹配                          |
| `validity.tooShort` / `tooLong`             | 长度不符                            |
| `validity.rangeUnderflow` / `rangeOverflow` | 超出范围                            |

`setCustomValidity` 的坑：一旦设置过非空消息，控件会一直处于 `customError` 状态，必须在校验通过时手动清空。

## 关掉原生校验

```html
<!-- 表单级：整体关闭 -->
<form novalidate>...</form>

<!-- 按钮级：提交时不校验 -->
<button type="submit" formnovalidate>保存草稿</button>
```

做自定义校验 UI 时通常用 `novalidate` 关闭气泡，再在 `submit` 事件里调用 `checkValidity()` 自己控制提示样式。

## 表单提交细节

```html
<form action="/api/feedback" method="post" enctype="multipart/form-data">
  <input type="file" name="attachment" accept="image/*" multiple />
  <button type="submit">提交</button>
</form>
```

- 含文件上传必须设置 `enctype="multipart/form-data"`
- `method` 只有 `get` 和 `post`，`put` / `delete` 需要 JavaScript
- 回车提交：表单里只有一个 `<button type="submit">` 时最可预测，多个按钮要明确 `type`

## 小结

- 优先用 `type`、`required`、`pattern` 表达约束，少写校验代码
- 数字用 `number`，标识类数字用 `text` + `inputmode`
- 自定义提示用 `setCustomValidity`，记得在校验通过时清空
- 复杂交互再上 `novalidate` + 自定义校验
