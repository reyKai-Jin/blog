轮询能做的事，WebSocket 和 SSE 往往做得更好。但两者定位不同：一个双向，一个单向。选错了，复杂度会翻倍。

<!-- more -->

## 先看对比

|                 | WebSocket          | SSE（EventSource）               |
| --------------- | ------------------ | -------------------------------- |
| 方向            | 双向               | 服务端 → 客户端单向              |
| 协议            | `ws://` / `wss://` | HTTP                             |
| 数据格式        | 文本或二进制       | UTF-8 文本                       |
| 自动重连        | 需要自己实现       | 浏览器内置                       |
| 请求头 / Cookie | 握手阶段可带       | 普通 HTTP 请求                   |
| 代理与网关      | 需要支持 Upgrade   | 和普通请求一致                   |
| 典型场景        | 聊天、协作、游戏   | 通知、进度、日志、大模型流式输出 |

一句话：需要客户端持续发消息，用 WebSocket；只需要服务端推送，用 SSE。

## WebSocket

### 建立连接

```js
const ws = new WebSocket("wss://example.com/ws");

ws.addEventListener("open", () => {
  console.log("已连接");
  ws.send(JSON.stringify({ type: "join", room: "tech" }));
});

ws.addEventListener("message", event => {
  const data = JSON.parse(event.data);
  console.log("收到", data);
});

ws.addEventListener("close", event => {
  console.log("连接关闭", event.code, event.reason, event.wasClean);
});

ws.addEventListener("error", () => {
  console.error("连接出错");
});
```

`readyState` 取值：`CONNECTING(0)`、`OPEN(1)`、`CLOSING(2)`、`CLOSED(3)`。

### 发送与关闭

```js
if (ws.readyState === WebSocket.OPEN) {
  ws.send("hello");
}

ws.close(1000, "正常关闭");
```

`send` 在非 `OPEN` 状态会抛异常，发送前要判断连接状态。

### 心跳与重连

连接可能被网络、网关、负载均衡器悄悄断开，需要应用层心跳：

```js
let heartbeatTimer;
let reconnectTimer;
let retries = 0;

function connect() {
  const ws = new WebSocket("wss://example.com/ws");

  ws.addEventListener("open", () => {
    retries = 0;
    heartbeatTimer = setInterval(() => {
      ws.send(JSON.stringify({ type: "ping" }));
    }, 30000);
  });

  ws.addEventListener("close", () => {
    clearInterval(heartbeatTimer);
    scheduleReconnect();
  });

  return ws;
}

function scheduleReconnect() {
  const delay = Math.min(1000 * 2 ** retries, 30000);
  retries += 1;
  reconnectTimer = setTimeout(connect, delay);
}
```

重连要加指数退避和上限，避免服务端故障时被客户端打满。

### 认证

浏览器 WebSocket API 不能自定义请求头，常见方案：

- 用 Cookie 认证（握手阶段自动携带）
- 连接后先发送一条 `auth` 消息，服务端验证通过前不推送业务数据
- 短时一次性 token 放在 URL 查询参数里（配合 HTTPS，注意日志泄露）

## SSE

### 客户端

```js
const source = new EventSource("/api/notifications");

source.addEventListener("open", () => {
  console.log("SSE 已连接");
});

source.addEventListener("message", event => {
  console.log("默认消息", event.data);
});

source.addEventListener("progress", event => {
  // 服务端发送的命名事件
  console.log("进度", JSON.parse(event.data));
});

source.addEventListener("error", () => {
  // 浏览器会自动重连；readyState 为 CLOSED 时表示已放弃
  if (source.readyState === EventSource.CLOSED) {
    console.error("SSE 连接已关闭");
  }
});
```

关闭连接：

```js
source.close();
```

`EventSource` 默认会断线重连，服务端可以返回 `retry: 5000` 控制重连间隔。

### 服务端格式

响应必须是 `Content-Type: text/event-stream`，消息以空行分隔：

```text
retry: 5000

event: progress
data: {"percent": 42}

data: 一行普通消息

data: 第一行
data: 第二行

```

- `data:` 可以多行，客户端会拼成带换行的字符串
- `event:` 指定事件名，客户端用 `addEventListener` 监听
- `id:` 用于断线续传，客户端重连时会带 `Last-Event-ID`
- `retry:` 指定重连毫秒数
- 以 `:` 开头的行是注释，常用来做心跳

Node.js 示例：

```js
app.get("/api/notifications", (req, res) => {
  res.setHeader("Content-Type", "text/event-stream");
  res.setHeader("Cache-Control", "no-cache");
  res.setHeader("Connection", "keep-alive");

  const timer = setInterval(() => {
    res.write(`event: progress\n`);
    res.write(`data: ${JSON.stringify({ percent: Date.now() % 100 })}\n\n`);
  }, 2000);

  req.on("close", () => clearInterval(timer));
});
```

### 限制

- 只支持 UTF-8 文本，二进制需要编码
- 同域下浏览器对 HTTP/1.1 的并发连接数有限制，HTTP/2 下没有这个问题
- 不能自定义请求头（原生 `EventSource`），需要鉴权时用 Cookie 或带 token 的查询参数

## 怎么选

- 聊天、协同编辑、在线游戏、需要客户端高频发送：WebSocket
- 通知、任务进度、日志流、AI 流式输出：SSE
- 只是偶尔刷新数据：轮询更简单，别过度设计

## 小结

- WebSocket 双向，SSE 单向；先确定数据流向再选型
- WebSocket 必须自己做心跳和重连
- SSE 自带重连，注意 `text/event-stream` 和消息格式
- 认证方案要结合浏览器限制设计
