个人站放视频，最容易犯的错是「把原始文件直接丢到服务器」。文件一大，带宽、加载速度和成本都会失控。这篇记录一套够用又便宜的视频处理流水线。

<!-- more -->

## 整体流程

```text
拍摄 / 导出
   ↓
预签名直传对象存储
   ↓
转码任务（H.264 / H.265 / HLS）
   ↓
CDN 分发 + 播放器按需加载
```

## 一、直传而不是中转

浏览器先向业务服务申请预签名地址，再直接上传到对象存储：

```ts
// 伪代码：获取预签名上传地址
const { uploadUrl, fileKey } = await api.post("/uploads/presign", {
  filename: file.name,
  contentType: file.type,
  size: file.size,
});

await fetch(uploadUrl, {
  method: "PUT",
  headers: { "Content-Type": file.type },
  body: file,
});
```

好处是应用服务器不转发大文件，上传带宽直接走对象存储。

## 二、转码参数

面向网页播放，优先保证兼容性和首屏速度：

| 场景 | 编码 | 分辨率 | 码率参考 |
| --- | --- | --- | --- |
| 桌面播放 | H.264 | 1080p | 6–10 Mbps |
| 移动端 | H.264 | 720p | 2.5–4 Mbps |
| 长视频 / 自适应 | HLS | 多档 | 按档位切片 |

FFmpeg 示例：

```bash
ffmpeg -i input.mov \
  -c:v libx264 -preset slow -crf 20 \
  -c:a aac -b:a 192k \
  -movflags +faststart \
  output.mp4
```

`-movflags +faststart` 会把索引信息放到文件头，避免边下边播时首帧等待过久。

## 三、HLS 切片（可选）

视频较长或需要自适应码率时，切成 HLS：

```bash
ffmpeg -i input.mp4 \
  -codec: copy \
  -start_number 0 \
  -hls_time 6 \
  -hls_list_size 0 \
  -f hls \
  index.m3u8
```

前端使用播放器（如 Video.js、hls.js）按需加载切片，用户不必等整个文件下载完。

## 四、封面与占位

转码时顺手抽帧生成封面：

```bash
ffmpeg -ss 00:00:03 -i input.mp4 -frames:v 1 -q:v 2 poster.jpg
```

封面图压缩后作为 `poster`，能显著改善列表页的加载体验。

## 五、CDN 与防盗链

- 视频域名单独使用 CDN，缓存策略按切片设置
- 开启 Referer 防盗链和签名 URL（按需）
- 原始素材放私有桶，公开桶只放转码产物
- 设置合理的生命周期规则，清理临时文件

:::

::: tip 成本控制
个人站流量通常不大，优先选择按量计费 + CDN 回源缓存。真正贵的往往不是存储，而是**冷门视频被反复回源**。开启缓存并设置较长的 `Cache-Control` 能省下大部分费用。
:::

一条稳定的媒体流水线，能让「拍完就能发」变成一件轻松的事。
