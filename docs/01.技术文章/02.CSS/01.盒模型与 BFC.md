「明明设了宽度 100%，为什么还溢出？」十有八九是盒模型没搞清楚；「为什么子元素的 margin 跑到父元素外面了？」则是 BFC 的问题。

## 两种盒模型

CSS 里每个元素都是一个盒子：

```text
┌─────────────────────────────┐
│           margin            │
│  ┌───────────────────────┐  │
│  │        border         │  │
│  │  ┌─────────────────┐  │  │
│  │  │    padding      │  │  │
│  │  │  ┌───────────┐  │  │  │
│  │  │  │  content  │  │  │  │
│  │  │  └───────────┘  │  │  │
│  │  └─────────────────┘  │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

`box-sizing` 决定 `width` 算的是哪一层：

| 值                    | `width` 的含义          | 实际占位                 |
| --------------------- | ----------------------- | ------------------------ |
| `content-box`（默认） | 只算内容区              | width + padding + border |
| `border-box`          | 内容 + padding + border | 就是 width               |

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

这几乎是每个项目的标准起手式。没有它，给元素加 `padding: 16px` 就会把 `width: 100%` 撑出容器。

## 块级元素与行内元素

- 块级盒：独占一行，`width` 默认撑满父元素
- 行内盒：和文字排在一行，`width` / `height` 不生效，垂直 `margin` 不生效
- `inline-block`：像文字一样排列，但可以设置宽高

```css
.tag {
  display: inline-block;
  padding: 2px 8px;
  border-radius: 999px;
}
```

## margin 合并

两个垂直相邻的块级元素，外边距会合并成一个，取较大值：

```css
.a {
  margin-bottom: 20px;
}
.b {
  margin-top: 30px;
}
/* 实际间距是 30px，不是 50px */
```

三种典型情况：

1. 相邻兄弟元素
2. 父子元素之间（父元素没有 border / padding / BFC 时）
3. 空元素自身的上下 margin

解决方案：用 `padding` 或 `gap` 代替垂直 `margin`，或者给父元素创建 BFC。

## 什么是 BFC

BFC（Block Formatting Context，块级格式化上下文）是一块独立的渲染区域，内部的布局不会影响外部。

### 触发方式

| 方式       | 示例                                                      |
| ---------- | --------------------------------------------------------- |
| `float`    | `float: left`                                             |
| `position` | `absolute` / `fixed`                                      |
| `display`  | `flow-root`、`inline-block`、`flex`、`grid`、`table-cell` |
| `overflow` | 非 `visible` 的值                                         |
| `contain`  | `layout` / `paint` / `strict` / `content`                 |

```css
.bfc {
  display: flow-root; /* 最干净的 BFC 触发方式 */
}
```

`display: flow-root` 专门为触发 BFC 而生，不影响其他布局行为，比 `overflow: hidden` 更安全。

### BFC 能解决的问题

**1. 清除浮动**

```css
.parent {
  display: flow-root;
}

.child {
  float: left;
  width: 200px;
  height: 100px;
}
```

父元素不会再因为子元素浮动而高度塌陷。

**2. 阻止 margin 穿透**

```css
.parent {
  display: flow-root;
}

.child {
  margin-top: 40px; /* 不再把父元素一起推下去 */
}
```

**3. 防止浮动文字环绕**

```css
.media {
  display: flow-root; /* 或者 overflow: hidden */
  margin-left: 120px;
}
```

**4. 自适应两栏布局**

```css
.sidebar {
  float: left;
  width: 240px;
}

.content {
  overflow: hidden; /* 触发 BFC，自动占满剩余空间 */
}
```

## 常见误区

- BFC 不是「清除浮动」的同义词，它解决的是布局隔离问题
- `overflow: hidden` 会裁剪溢出内容，弹窗、下拉菜单里慎用
- 用了 Flex / Grid 的容器本身就是格式化上下文，很多老 BFC 技巧不再需要

## 小结

- 全局 `box-sizing: border-box` 是基础
- 垂直间距优先用 `padding` 或 `gap`，不要依赖 margin 叠加
- 需要 BFC 时优先 `display: flow-root`
- 现代布局优先 Flex / Grid，BFC 更多用于兜底和兼容旧代码
