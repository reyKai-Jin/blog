「样式为什么不生效？」大部分时候不是写错了属性，而是优先级输给了别的规则。搞懂层叠规则，调试效率会高很多。

## 常见选择器

```css
/* 类型 */
p {
}

/* 类 */
.card {
}

/* ID */
#app {
}

/* 属性 */
input[type="email"] {
}

/* 后代 */
.card .title {
}

/* 子元素 */
.card > .title {
}

/* 相邻兄弟 */
.title + .meta {
}

/* 通用兄弟 */
.title ~ .meta {
}
```

## 伪类与伪元素

```css
/* 伪类：元素的状态或位置 */
a:hover {
}
li:first-child {
}
input:focus-visible {
}
.card:has(img) {
}

/* 伪元素：元素的某个部分 */
.card::before {
  content: "";
}
p::first-line {
}
```

冒号数量：伪类一个 `:`，伪元素两个 `::`。`::before` / `::after` 必须配合 `content` 才会显示。

## 优先级计算

优先级用四元组表示：`(行内样式, ID, 类/属性/伪类, 元素/伪元素)`。

| 选择器        | 优先级               |
| ------------- | -------------------- |
| `*`           | 0,0,0,0              |
| `p`           | 0,0,0,1              |
| `.card`       | 0,0,1,0              |
| `#app`        | 0,1,0,0              |
| `style="..."` | 1,0,0,0              |
| `!important`  | 最高（覆盖行内样式） |

```css
/* 0,0,2,1 */
.card .title:hover {
}

/* 0,0,3,0 */
.nav .menu .link {
}
```

比较规则：从左往右逐位比较，不会进位。也就是说 11 个类也赢不了 1 个 ID。

`*`、`>`、`+`、`~` 不贡献优先级。

## :is、:where、:not

```css
/* :is 取参数中优先级最高的那个 */
:is(.card, #hero) .title {
}

/* :where 优先级恒为 0，适合写可被覆盖的基础样式 */
:where(.card) .title {
}

/* :not 的优先级等于参数本身的优先级 */
.card:not(.is-active) {
}
```

`:where` 在写组件库、重置样式时特别有用，不会无意中抬高优先级。

## 层叠顺序

同一元素上有多条冲突规则时，按下面的顺序决胜：

1. 重要性：`!important` > 普通声明
2. 来源：用户代理（浏览器默认）< 用户样式 < 作者样式
3. 优先级：比较四元组
4. 书写顺序：后写的覆盖先写的

CSS Cascade Layers 可以显式控制来源顺序：

```css
@layer reset, base, components, utilities;

@layer base {
  .card {
    padding: 16px;
  }
}

@layer components {
  .card {
    padding: 24px;
  }
}
```

后声明的 layer 优先级更高，与选择器权重无关。这是大型项目控制样式覆盖最干净的方式之一。

## 继承

部分属性会自动继承：`color`、`font-family`、`font-size`、`line-height` 等。

```css
body {
  color: #111827;
  font-family: system-ui, sans-serif;
}
```

显式控制继承：

```css
.child {
  color: inherit; /* 继承父元素 */
  color: initial; /* 恢复属性初始值 */
  color: unset; /* 可继承属性等同 inherit，否则等同 initial */
  color: revert; /* 回退到浏览器或用户样式 */
}
```

## 调试建议

- 用开发者工具的 Computed 面板看最终生效的规则和被划掉的规则
- 不要用 `!important` 解决问题，先检查选择器是否写得太深
- 组件样式尽量用单类选择器，降低耦合
- 避免用 ID 写样式，ID 留给锚点和 JavaScript

## 小结

- 优先级按 `(行内, ID, 类, 元素)` 比较，不会进位
- 伪类算类，伪元素算元素
- `:where` 优先级为 0，适合基础样式
- 结构复杂时用 `@layer` 管理覆盖关系
- 少用 `!important` 和深层嵌套选择器
